OwnChat 是一款自用 AI 客户端，使用原生 HTML / CSS / JavaScript 实现，不需要后端服务和构建步骤。它支持 **对话模式** 和 **绘画模式**，配置、会话、附件和绘画历史都保存在当前浏览器本地。

> 适合个人部署、自用模型网关、OpenAI-compatible 服务、临时调试多模型配置等场景。
>
> 面向公众提供生成式人工智能服务时，使用者应遵守《生成式人工智能服务管理暂行办法》等监管要求，自行完成所在司法辖区要求的备案、许可、内容安全、实名、日志留存、税务和上游授权等合规义务。

## 特性

- **纯前端运行**：无框架、无构建步骤，直接部署静态文件即可。
- **轻量化**：不计算 Markdown 渲染插件 `markdown-it.min.js` 时，整个项目大小仅约 598 KB。
- **对话和绘画双模式**：顶部快速切换，两个模式的配置和模型互相隔离。
- **OpenAI-compatible**：对话兼容 Chat Completions；绘画兼容 Images API，并支持 Responses API 映射模式。
- **Service Worker 代理**：支持刷新后恢复流式回复和图片生成结果；SW 不可用时自动回退到页面请求。
- **多会话管理**：新建、切换、重命名、删除、批量删除、搜索对话和绘画历史。
- **角色设定**：每个对话都可以设置独立 system prompt。
- **Markdown 渲染**：基于本地 `markdown-it`，支持表格、任务列表、代码块、图片链接和代码复制。
- **Reasoning 展示**：支持 `reasoning_content`、`thinking` 字段和 `<think>...</think>` 内容的折叠展示；复制回答时不会复制思考过程。
- **上文管理**：支持携带上文上限、上文已用量和裁剪阈值提示、单次发送是否携带上文，超出上限时自动裁剪旧消息。
- **真实用量优先**：流式请求会尝试启用 `stream_options.include_usage`，优先显示接口返回的输入、输出、总计 token；不支持时回退到本地估算。
- **耗时拆分**：思考耗时显示在思考过程折叠块标题中，消息 meta 显示首字耗时和正文输出耗时。
- **文件上传**：对话支持图片和常见文本/代码文件；大文件内容存入 IndexedDB，重新生成会保留原消息附件。
- **绘画多轮编辑**：图片编辑、重绘和参考图编辑会在当前绘画对话中继续追加，不会强制新开记录。
- **图片查看器**：生成图和参考图支持点击查看、滚轮缩放、拖拽移动、复制和下载。
- **图片元信息**：显示实际尺寸、格式、文件大小、模型、耗时和完成时间。
- **提示词优化**：绘画模式可单独配置提示词优化模型，通过 AI 改写绘画提示词。
- **配置管理**：支持含密钥配置导出、JSON 导入，以及 URL 参数快速导入。
- **移动端适配**：侧栏、设置弹窗、模型选择、输入区和绘画状态都做了响应式布局。
- **主题切换**：支持浅色和深色主题，刷新时避免主题和模式闪屏。

## 快速开始

### 方式一：直接打开

直接用浏览器打开 `index.html` 即可使用基础功能。

注意：直接使用 `file://` 打开时，Service Worker 无法注册，刷新恢复能力不可用。推荐使用本地静态服务器。

### 方式二：本地静态服务器

在项目目录运行任意静态服务器：

```bash
php -S 127.0.0.1:8097
```

或：

```bash
python3 -m http.server 8097
```

然后打开：

```text
http://127.0.0.1:8097
```

### 首次配置

首次打开可以选择「稍后配置」。未配置时仍可浏览界面和切换模式，只有点击发送、生成、编辑或优化时才会提示配置。

对话配置：

1. 打开「设置 → 对话」。
2. 填写 Base URL，例如 `https://api.openai.com/v1`。
3. 填写 API Key。
4. 刷新模型列表或手动填写模型名。
5. 保存后开始对话。

绘画配置：

1. 打开「设置 → 绘画」。
2. 填写 Image Base URL 和 Image API Key。
3. 选择或手动填写绘画模型，默认推荐 `gpt-image-2`。
4. 可选填写映射模型和提示词优化模型。
5. 保存后开始生成图片。

## 配置说明

OwnChat 把对话配置和绘画配置完全隔离：

| 配置项 | 对话模式 | 绘画模式 |
| --- | --- | --- |
| Base URL | 独立 | 独立 |
| API Key | 独立 | 独立 |
| 当前模型 | 对话模型 | 绘画模型 |
| 模型列表缓存 | 对话模型列表 | 绘画模型列表 |
| 参数 | Temperature、Top P、回复长度上限、携带上文上限 | 尺寸、质量、格式、背景 |

### 模型选择

- 顶部模型下拉会跟随当前模式显示对应模型。
- 设置里可以从 `/models` 获取模型，也可以手动填写未出现在列表里的模型名。
- 绘画模式如果启用了映射模型，顶部会显示 `映射 xxx`；可以在模型下拉中关闭映射，回到原绘画模型。

### 配置导入导出

设置窗口顶部提供配置管理工具：

- **导出配置**：导出完整配置，默认包含对话和绘画 API Key，适合私人设备迁移。
- **导入配置**：从 JSON 文件恢复配置，导入前会显示确认预览。

> 导出的 JSON 会包含密钥，不建议分享给他人或保存在不可信设备上。

### URL 快速导入配置

支持通过 GET 参数快速写入配置，适合从自己的配置页、脚本或书签链接打开 OwnChat。

支持参数：

- `config`：URL 编码后的 JSON 字符串
- `config_b64`：base64url 编码后的 JSON 字符串
- `oc_config`：`config` 的别名
- `oc_config_b64`：`config_b64` 的别名

示例：

```json
{
  "mode": "chat",
  "chat": {
    "baseUrl": "https://api.openai.com/v1",
    "apiKey": "sk-...",
    "model": "gpt-4o",
    "models": ["gpt-4o", "gpt-4o-mini"]
  },
  "image": {
    "baseUrl": "https://api.openai.com/v1",
    "apiKey": "sk-...",
    "model": "gpt-image-2",
    "mapModel": "",
    "promptModel": "gpt-4o-mini",
    "models": ["gpt-image-2", "gpt-4o-mini"],
    "defaults": {
      "size": "auto",
      "quality": "auto",
      "outputFormat": "png",
      "background": "auto"
    }
  }
}
```

URL 形式：

```text
index.html?config=%7B%22chat%22%3A%7B%22baseUrl%22%3A%22https%3A%2F%2Fapi.openai.com%2Fv1%22%2C%22apiKey%22%3A%22sk-...%22%2C%22model%22%3A%22gpt-4o%22%7D%7D
```

识别到 URL 配置后，应用会弹出确认预览，并对 API Key 脱敏显示。确认导入后才会写入本地存储，并自动从地址栏移除配置参数。

> GET URL 可能被浏览器历史、代理或服务器访问日志记录，不建议在公共环境传递长期有效的 API Key。

## 对话模式

对话模式使用接口：

```text
POST /v1/chat/completions
GET  /v1/models
```

主要能力：

- 新建、切换、重命名、删除、批量删除对话
- 搜索对话标题、角色设定和消息内容
- 每个对话独立角色设定，并作为 `system` 消息发送
- 流式输出，支持停止生成和重新生成；带附件消息重新生成时会复用原附件
- 切换对话时正在生成的回复可继续在后台进行
- 回复生成期间会尽量申请屏幕唤醒，减少移动端自动息屏导致的连接中断
- Markdown 渲染、代码高亮、代码复制
- reasoning / thinking 折叠展示
- 对话复制支持「复制回答」，不会复制思考过程
- 图片和文本文件上传
- Token 统计：用一句话提示上文已用多少、再增加多少会触发裁剪
- 携带上文超出上限时自动裁剪旧消息，并保留 system 消息和最后一轮上下文
- 每个对话独立设置 Temperature、Top P、回复长度上限、携带上文上限

### Token 和上文

- **携带上文上限**：控制本次请求最多携带多少历史消息，默认 128K。设为 `0` 表示不裁剪。
- **携带上文**：输入框工具栏可以按次关闭上文；关闭后本次请求只发送当前用户消息和 system prompt，历史仍保存在本地。
- **裁剪提示**：顶部会显示类似 `上文已用 2.7K，再增加 125K 会裁剪` 的提示；这里描述的是携带上文额度，不表示模型可输出空间。
- **回复长度上限**：界面单位为 K tokens，对应请求中的 `max_tokens`，限制单次回答长度，通常不需要修改。
- **Token 用量**：如果服务支持流式 usage，消息底部显示接口返回的 `输入 / 输出 / 总计`；否则显示 `~tokens`，表示本地估算值。
- **耗时显示**：`首字` 表示从请求开始到首个正文 token 到达的时间；`输出` 表示从首个正文 token 到回复结束的时间；思考耗时只显示在「思考过程」标题里。

当携带上文已超出上限时，发送前会提示：

```text
携带上文已超出上限，本次将自动裁剪旧消息
```

## 绘画模式

绘画模式支持三条路径：

| 场景 | 接口 |
| --- | --- |
| 文生图 | `POST /v1/images/generations` |
| 参考图编辑 | `POST /v1/images/edits` |
| 映射模式 | `POST /v1/responses` + `image_generation` 工具 |

主要能力：

- 独立绘画 Base URL、API Key 和模型配置
- 尺寸、质量、输出格式、背景参数
- 默认尺寸支持 `auto`，也支持 `1024x1024`、`1536x1024`、`1024x1536`、`3840x2160`、`2160x3840`
- 一次生成一张图片
- 生成中状态、预计耗时、已等待时间和取消按钮
- 图片生成期间会尽量申请屏幕唤醒，减少手机自动息屏导致的中断
- 生成完成后显示实际耗时、模型、尺寸、格式和文件大小
- 图片点击放大查看，支持滚轮缩放、拖拽移动、复制、下载
- 从结果图继续「以图编辑」
- 上传参考图进行编辑
- 编辑和重绘会在当前绘画对话中追加，不会新开记录
- 每一轮用户提示词都显示时间、Token 估算、复制和复用按钮
- 历史记录支持搜索、重命名、删除、批量删除和占用统计

### 多轮图片编辑

绘画模式使用类似聊天的左右消息结构：

```text
用户：提示词 / 参考图
AI：生成图片
用户：基于参考图进行编辑：...
AI：编辑后的图片
```

点击「编辑」或「以图编辑」后，输入框会自动填入：

```text
基于参考图进行编辑：
```

提交后会在当前绘画对话中追加新一轮用户消息和 AI 图片回复。原提示词、原图片、原模型、原时间和原结果都会保留。

### 提示词优化

绘画输入框左侧的闪光按钮用于优化当前提示词。该功能使用「设置 → 绘画」里的提示词优化模型。

隔离规则：

- 提示词优化模型可以选择对话模型或绘画模型。
- 选择对话模型时使用对话 Base URL 和 API Key；选择绘画模型时使用绘画 Base URL 和 API Key。
- 优化模型只负责改写提示词，不参与实际生图。
- 实际生图仍由绘画模型或映射模型完成。
- 未配置提示词优化模型时，点击优化会打开绘画设置。

### 映射模式

映射模式适合让通用模型通过工具调用来生成图片。启用后，OwnChat 会请求 `/v1/responses`，并要求映射模型调用 `image_generation` 工具。

逻辑：

```text
用户提示词 / 参考图
  -> 映射模型
  -> tool_choice: required
  -> image_generation 工具
  -> 返回图片
```

注意：

- 映射模型不是直接生图，真正生成图片的是 `image_generation` 工具。
- 映射模型可以选择对话模型或绘画模型；对话模型调用对话配置，绘画模型调用绘画配置。
- 有参考图时，参考图会作为 `input_image` 一起发送。
- 关闭映射模型后，会回到 Images API 流程。
- 不是所有 OpenAI-compatible 服务都支持 Responses API 或 `image_generation` 工具。

## Service Worker 代理

OwnChat 注册 `sw.js` 后，会把对话流式请求和图片生成请求交给 Service Worker 执行，页面通过 IndexedDB 读取进度和结果。

能力：

- 刷新页面后恢复流式回复
- 刷新页面后恢复图片生成结果
- 切换对话不打断后台流式回复
- 避免页面和 SW 同时重复请求
- 在支持 usage 的服务上保存流式 token 用量和输出耗时

基本流程：

```text
页面 postMessage -> Service Worker fetch -> 写入 IndexedDB -> 页面轮询读取 -> 更新 UI
```

如果浏览器不支持 Service Worker，或页面不是 HTTPS / localhost，应用会自动回退到页面直接请求模式。回退模式仍可使用，但刷新恢复能力会下降。

### 图片生成恢复

SW 模式下，图片生成会话保存在 `ownchat_stream_db` 的 `image_generation` 记录中。刷新后页面会检查该记录：

- `complete`：恢复结果
- `streaming` / `connecting`：继续轮询等待
- `stopped` / `error`：标记为中断或失败
- 长时间无更新：标记超时

移动端浏览器在息屏、锁屏、切到后台或系统省电策略介入时，仍可能暂停页面和 Service Worker。OwnChat 会在对话回复和图片生成期间尽量使用 Screen Wake Lock 防止自动息屏，但纯前端无法保证后台任务一定持续执行；如果需要面向生产环境稳定生成，建议使用后端任务队列托管长请求，前端只轮询任务状态。

## 本地存储

OwnChat 不主动把配置和历史发送给除你配置的 API 服务之外的第三方。

| 存储位置 | 内容 |
| --- | --- |
| `localStorage` | 对话配置、对话文本、绘画配置、主题、当前模式、Token 统计 |
| `IndexedDB: ownchat_stream_db` | SW 流式会话和图片生成临时会话 |
| `IndexedDB: ownchat_image_db` | 绘画历史、生成图片、对话文件附件 |

存储策略：

- 对话文本放在 localStorage。
- 对话附件和绘画图片放在 IndexedDB，避免 localStorage 配额不足。
- 绘画图片体积较大，历史过多时可在左侧绘画列表使用批量删除清理。
- 如果浏览器清理站点数据，配置、对话和图片历史都会被清除。

## 部署

需要部署的文件：

```text
index.html
style.css
app.js
sw.js
icon.png
markdown-it.min.js
```

可以部署到：

- Nginx / Apache
- GitHub Pages
- Cloudflare Pages
- Vercel / Netlify 静态站点
- 任意本地静态服务器

注意：

- Service Worker 要求 HTTPS 或 localhost。
- 如果你的 API 服务没有开放 CORS，纯前端页面无法直接请求，需要服务端或网关支持 CORS。
- 如果部署路径不是根目录，通常不需要额外配置；确保 `sw.js`、`app.js`、`style.css` 和 `markdown-it.min.js` 路径可访问即可。

项目结构：


1. 关闭所有 OwnChat 标签页后重新打开。
2. 或在 DevTools -> Application -> Service Workers 中手动更新。
3. 或清理站点数据后重新加载。

建议检查：

```bash
node --check app.js
```

## 常见问题

### 为什么出现 `Failed to fetch`？

常见原因：

- Base URL 不正确
- API 服务不可访问
- API 服务没有开放 CORS
- 浏览器阻止了混合内容，例如 HTTPS 页面请求 HTTP API
- 本地网络、代理或证书问题
- Service Worker 还没有接管页面，刷新一次通常可以注册完成

### 为什么 `/style.css` 后面有版本号？

浏览器或开发服务器可能为了缓存控制追加查询参数。只要文件正常加载，功能不受影响。

### 为什么模型列表里没有我想用的模型？

很多 OpenAI-compatible 服务的 `/models` 不会完整区分模型类型。可以在设置里手动填写模型名。

### 为什么有时显示 `~tokens`？

`~tokens` 表示本地估算值。OwnChat 会在流式请求中尝试携带 `stream_options: { include_usage: true }`，如果上游服务支持，会显示接口返回的 `输入 / 输出 / 总计`；如果上游不支持、没有返回 usage，或拒绝该参数，OwnChat 会自动重试并回退到本地估算。

### `首字`、`输出` 和 `思考过程` 的时间有什么区别？

- `首字`：从发起请求到第一个正文 token 到达的时间。
- `输出`：从第一个正文 token 到回复完成的正文生成时间。
- `思考过程 · Xs`：模型 reasoning / thinking 阶段耗时，只在思考折叠块标题里显示。

### 为什么图片复制失败？

如果服务返回的是远程图片 URL，浏览器可能因为 CORS 限制无法把图片写入剪贴板。此时 OwnChat 会尽量复制图片链接，或建议下载后使用。

### 为什么刷新后图片生成没有恢复？

可能原因：

- 页面通过 `file://` 打开，Service Worker 不可用
- 当前浏览器不支持或禁用了 Service Worker
- 生成请求在 SW 接管前已经由页面直接发起
- 浏览器终止了后台 SW
- 手机息屏、锁屏、切到后台或省电策略暂停了浏览器
- IndexedDB 被清理或不可用

### 为什么历史图片占用越来越大？

生成图片以 base64 或 Blob 等形式保存在 IndexedDB 中，体积会比较大。「设置 → 绘画」会显示历史数量、图片数量和存储占用；需要清理时可在左侧绘画列表使用「批量删除」。
